# 1️⃣ 개념정리

## 5-2. JOIN 이해하기

~~~
✅ 학습 목표 :
* JOIN에 대한 정의와 필요성에 대해 설명할 수 있다.
~~~

서로 다른 데이터 테이블을 연결하는 것
두 데이터를 연결하는 공통 값이 없다! -> 트레이너 id, 포켓몬 id를 연결
Join : 트레이너가 포획한 포켓몬 기준으로 트레이너 데이터를 연결하기
(trainer_id 컬럼 기준으로) 공통 key로 붙이기
여러 테이블 join 가능, 필요한거 select
보통 id값을 key로 많이 사용하고, 특정 범위로도 가능


### join을 해야하는 이유
관계형 데이터베이스는 설계시 정규화 과정을 거침
정규화는 중복을 최소화하게 데이터를 구조화함. 그래서 필요할 때 join함
근데, 개별 관점에선 분리되어 있는 것이 좋음

대신 데이터 웨어하우스에서 join+필요한 연산을 해서 '데이터 마트'를 만들어서 활용

## 5-3. 다양한 JOIN 방법

~~~
✅ 학습 목표 :
* JOIN 방법들의 종류를 설명할 수 있다. 
* 각 JOIN 방법들의 차이점에 대해서 설명할 수 있다. 
~~~

INNER JOIN: 두 테이블의 공통 요소만 연결(교집합)
LEFT/RIGHT JOIN: 왼쪽 기준으로 연결
FULL JOIN: 양쪽 기준으로 연결(합집합)
CROSS JOIN: 두 테이블의 각각 요소를 곱함





## 5-4. JOIN 쿼리 작성하기 

~~~
✅ 학습 목표 :
* JOIN을 사용한 문법에 대해 이해하여 적용할 수 있다.
* JOIN 을 활용한 쿼리를 작성할 수 있다. 
~~~

테이블 확인-> 데이터, 컬럼 확인-> 기준 테이블 정의(ROW 수가 적은)
-> JOIN KEY 찾기-> 결과 예상하기-> 쿼리 작성.검증

CROSS JOIN은 ON 필요 없음


## 5-6. JOIN 연습문제 1~5번 

~~~
✅ 학습 목표 :
* 연습문제(3문제 이상) 푼 것들 정리하기
~~~

1번문제: jojn key: trainer_pokemon
trainer_pokemon에서 where로 active, training인 경우만(status) 필터림
연산량 관점에서 먼저 row수를 줄이고, join하는 게 효율적
서브쿼리를 만듦. 
join에서 중복된 컬럼의 이름이 있으면 꼭 어떤 테이블의 컬럼인지 명시해줘야 함(ex. p.kor_name)
1 = 1: 무조건 true를 반환 => 모든 row를 출력해라! -> AND 쓰고, 빠르게 주석 처리

2번문제: trainer_pokemon 테이블(트레이너가 잡은 히스토리가 저장됨)
pokemon 테이블(모든 포켓몬의 정보가 저장됨)
join을 할 수 있는 key 같아보이는 게 많은 테이블을 제일 왼쪽으로 둠(예외 존재)

3번문제: join key: trainer.id = trainer_pokemon.trainer_id
trainer를 왼쪽으로 두고 쿼리 구성.
triner 테이블에는 "Goh"가 하나만 있음 -> 특정 트레이너의 정보가 1개 들어있음
join을 하다보면 right에서 left의 기준에 여러개가 있을 때 데이터가 더 많아지는 것처럼 보임
(기준 차이땜에)
distinct 사용해서 unique를 구해줌
